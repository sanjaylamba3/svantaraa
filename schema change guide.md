# Schema Change & Migration Guide

This guide covers everything you need to know when modifying collections, globals, or fields in Payload CMS 3 (with PostgreSQL & Drizzle ORM).

---

## Why Migrations are Required

In `src/payload.config.ts`, the PostgreSQL adapter has:
```ts
db: postgresAdapter({
  pool: { connectionString: env.DATABASE_URL },
  push: false, // Drizzle auto-push is disabled
})
```
- **`push: false`** prevents automatic, uncontrolled altering of your database tables while running the dev server.
- Every schema change (adding, renaming, or deleting fields/collections) must be recorded in a migration file and applied via SQL statements generated by Drizzle.

---

## Quick Reference Workflow

Whenever you change any schema in `src/collections/` or `src/globals/`:

| Step | Command | What It Does |
| :--- | :--- | :--- |
| **1. Create Migration** | `pnpm payload migrate:create "descriptive_name"` | Compares your code against the last schema snapshot and generates a new `.ts` migration file in `src/migrations/`. |
| **2. Apply Migration** | `pnpm payload migrate` | Executes pending migrations against your database. |
| **3. Regenerate Types** | `pnpm generate:types` | Updates `src/payload-types.ts` so TypeScript and your components recognize new/renamed fields. |
| **4. Verify Build** | `pnpm build` | Compiles Next.js to ensure no frontend components or queries are broken by the change. |

---

## Step-by-Step Scenarios

### Scenario A: Adding a New Field

1. Add the field definition to your collection or global (e.g. `src/globals/Homepage.ts`).
2. Run:
   ```bash
   pnpm payload migrate:create "add_my_new_field"
   ```
   *(Drizzle will generate `ALTER TABLE ... ADD COLUMN ...` automatically)*
3. Run:
   ```bash
   pnpm payload migrate
   ```
4. Run:
   ```bash
   pnpm generate:types
   ```

---

### Scenario B: Renaming an Existing Field or Enum (Important!)

When you rename a field or an option list (enum) in Payload, Drizzle cannot automatically tell whether you renamed the existing column or deleted the old one and created a brand new one.

1. Rename the field in your code (e.g. `slowTravelerSection` &rarr; `aboutSection`).
2. Run in your terminal:
   ```bash
   pnpm payload migrate:create "rename_field_name"
   ```
3. **Handle Interactive Prompts (UP Statements):**
   - Drizzle will ask questions like:
     ```text
     Is about_section_heading column in homepage table created or renamed from another column?
       + about_section_heading                                                 create column
     ❯ ~ slow_traveler_section_heading › about_section_heading                 rename column
     ```
   - **Always select `rename`** using your arrow keys and press `Enter` if you want to preserve existing database records.
   - If you select `create`, the old column will be deleted (dropping data) and an empty new column will be created.
4. **Handle DOWN Statements:**
   - Drizzle will ask the reverse for rollbacks. Select the corresponding rename pair and press `Enter`.
5. Run:
   ```bash
   pnpm payload migrate
   ```
6. Run:
   ```bash
   pnpm generate:types
   ```
7. Update any frontend components that consumed the old field name.

---

### Scenario C: Deleting a Field

1. Remove the field from your collection/global file.
2. Run:
   ```bash
   pnpm payload migrate:create "remove_field_name"
   ```
3. Run:
   ```bash
   pnpm payload migrate
   ```
4. Run:
   ```bash
   pnpm generate:types
   ```

## Helpful Commands

### Check Migration Status
See which migrations have already run and which are pending:
```bash
pnpm payload migrate:status
```

### Roll Back the Most Recent Migration
If you made a mistake or want to undo the latest migration:
```bash
pnpm payload migrate:down
```

### Regenerate Import Map
If you add or rename custom components in admin views/blocks:
```bash
pnpm generate:importmap
```

## Common Errors & Troubleshooting

### 1. `column "x" does not exist` (DrizzleQueryError)
- **Cause:** You changed/added a field in your schema files, but haven't run `migrate:create` and `migrate` yet.
- **Fix:** Run `pnpm payload migrate:create "name"` followed by `pnpm payload migrate`.

### 2. Migration command hangs without output
- **Cause:** Drizzle is waiting for interactive input (such as confirming a rename vs create), but the terminal running it doesn't support interactive TTY.
- **Fix:** Always run `pnpm payload migrate:create` directly in your interactive terminal, not via non-interactive scripts.

### 3. Type errors in frontend components
- **Cause:** Schema was updated, but `payload-types.ts` is still using the old types.
- **Fix:** Run `pnpm generate:types`.

## Vercel / CI Deployment

- When deploying to Vercel, the build command runs `pnpm ci:build`:
  ```bash
  payload migrate && payload generate:importmap && next build
  ```
- Any committed migration files in `src/migrations/` will automatically be executed against the connected database before Next.js builds.
